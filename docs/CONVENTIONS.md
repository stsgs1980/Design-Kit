# Правила кода и проверки

Источник правил — шаблон [stsgs1980/webstorm-config](https://github.com/stsgs1980/webstorm-config)
(ESLint + Prettier + markdownlint + TypeScript strict + Husky + AI Rules). Здесь — что именно взято,
чем это проверяется в этом репозитории и какие отличия сделаны осознанно.

| ------------------------ | -------------------- | ---------------------------------- |
| Отступ                   | 2 пробела            | `.editorconfig`                    |
| Кавычки                  | двойные              | `.prettierrc`                      |
| Точка с запятой          | обязательна          | `.prettierrc`                      |
| Висячие запятые          | везде, где допустимо | `.prettierrc`                      |

```bash
npm run format        # отформатировать всё

```

## 2. TypeScript и JSDoc

- `strict: true`, `noEmit: true`, `isolatedModules` — как в шаблоне.
- У каждой функции явный тип возвращаемого значения (`@typescript-eslint/explicit-function-return-type`).
  Компоненты — `ReactElement`, асинхронные — `Promise<ReactElement>`.
- `any` запрещён (`@typescript-eslint/no-recommended` → `no-explicit-any`).
- `console.log` запрещён; разрешены `console.warn` и `console.error` (`no-console`).
- JSDoc обязателен для публичного API: экспортируемые функции, компоненты, методы
  (`jsdoc/require-jsdoc` c `publicOnly`). В TypeScript `@param`/`@returns` не нужны — типы и есть источник истины.
- Хуки и утилиты описываются одной строкой по-русски: зачем они нужны, а не что делают механически.

```bash
npm run lint       # ESLint, 0 предупреждений
npm run typecheck  # tsc --noEmit
```

## 3. Анти-монолит

Пороги из AI Rules шаблона:

| Объект     | Предел                                | Проверка                           |
| ---------- | ------------------------------------- | ---------------------------------- |
| Файл TS/JS | 250 строк                             | `npm run check:file-length`        |
| Компонент  | 200 строк                             | ревью, разделение на подкомпоненты |
| Функция    | 50 строк, цикломатика ≤ 15            | ревью в WebStorm                   |
| `useState` | 3+ в одном компоненте → вынести в хук | ревью                              |

```bash
npm run check:file-length   # весь репозиторий, тесты освобождены
```

При превышении: остановиться, назвать причину, разделить на модули, продолжить задачу. Файл, который
перевалил за предел, не «дорабатывается по мелочи» — он сразу делится.

## 4. Юникод-политика

`eslint-rules/unicode-policy.mjs` запрещает эмодзи и псевдографику в коде и в блоках кода внутри
Markdown. Вместо символов — текстовые теги:

| Ситуация            | Тег       |
| ------------------- | --------- |
| Готово, берём       | `[OK]`    |
| Нужна адаптация     | `[ADAPT]` |
| Отклонено, не берём | `[NO]`    |
| Проверка провалена  | `[FAIL]`  |
| Ещё не сделано      | `[TODO]`  |

Правила замены по всему репозиторию:

- эмодзи (в том числе эмодзи-галочки и ключи) — только теги из таблицы;
- символы рисования рамок и блоков — `+-` для ветвей дерева, `|` для вертикалей;
- стрелки в прозе и комментариях — `->` и `<->`;
- знаки «да/нет» в выводе скриптов — `[OK]` / `[FAIL]`.

Прозу в `.md` ESLint не проверяет (правило работает на сниппетах), поэтому в тексте действует то же
соглашение — проверяется глазами по чеклисту.

## 4a. Цвет

- Один громкий акцент на экран: `--primary` (циан) — действие, выбор, фокус.
- `--warm` (оранжевый) — **только сигнал**, а не второй акцент: цена в JS у записи кита,
  вердикт «на подъёме» у паттерна. В фонах и градиентах он не участвует — иначе два
  громких цвета спорят и иерархия рассыпается.
- Тема по умолчанию — **тёмная**: сервер всегда отдаёт явный класс на `<html>`, поэтому страница
  не зависит от настройки ОС и от того, дошла ли cookie. Выбор человека дублируется в `localStorage`
  и применяется загрузочным скриптом до первой отрисовки: в песочнице превью cookie не сохраняется.
- Тема на `<html>` — это **класс и только класс**: `color-scheme` берётся из него (`.light` / `.dark`
  в `app/globals.css`). Инлайновый `style` на `<html>` запрещён — React сверяет атрибуты при
  гидрации и рапортует рассинхрон («A tree hydrated but some attributes…»). Скрипт, который меняет
  класс до гидрации, поэтому работает с `suppressHydrationWarning`: побеждает DOM.
- Текст на заливке `--primary` — тёмные чернила (`--primary-foreground`): белый на `#00a5ef`
  даёт контраст 2.9:1 и не проходит AA.
- Цвета живут только в токенах `app/globals.css` через `light-dark()`. Хардкод `#…` в
  компонентах допустим лишь там, где цвет — часть демонстрируемого эффекта.

| Токен                | Роль                        | Где живёт                        |
| -------------------- | --------------------------- | -------------------------------- |
| `--primary`          | единственный громкий акцент | кнопки, активные вкладки, ссылки |
| `--warm`             | сигнал: цена и «на подъёме» | сайдбар каталога, чип вердикта   |
| `--muted-foreground` | второй план: подписи, цифры | везде                            |

## 4b. Вендорные каталоги

Скилы агентов в репозитории **не лежат**: они приходят из глобальной установки
(плагин opencode, каталог `~/.agents`). Копия в `.claude/skills` была бы дублем
глобального набора в каждом проекте — и проекты начали бы тянуть разные версии
одних и тех же скилов.

Но чужой код всё равно может попасть в проект (`npx skills add`, `.cursor/rules`,
`.windsurf/rules`), и он приезжает со своими emoji, `console.log`, файлами на 700
строк и невыровненным markdown — то есть ломает ровно те правила, которые мы
держим для своего кода.

Правило: такой каталог объявляется в одном месте — `scripts/lib/vendor-dirs.mjs` —
и исключается **из всех** проверок сразу. Пять инструментов собирают файлы
по-своему (eslint, prettier, markdownlint, tsc, анти-монолит), и один забытый
игнор роняет сборку на чужом коде.

| Инструмент   | Где исключение                                   |
| ------------ | ------------------------------------------------ |
| eslint       | `VENDOR_GLOBS` в `eslint.config.mjs`             |
| prettier     | `.prettierignore`                                |
| markdownlint | `--ignore .claude` в скрипте `lint:md`           |
| tsc          | `exclude` в `tsconfig.json`                      |
| анти-монолит | `isVendored()` в `scripts/check-file-length.mjs` |

`npm run verify:vendor` проверяет обе стороны: каталог, лежащий на диске, обязан
быть объявлен в `VENDOR_DIRS` (иначе чужой код снова попадёт под гейты), а
объявленный — исключен у всех пяти инструментов. Плюс проверяет, что наш код не
импортирует из вендорного каталога: скилы не должны протекать в бандл. Гейт висит
и на `pre-commit`, и на `pre-push`.

Установка скилов — глобальная, вне проекта: `npx skills add obra/superpowers`.
`npx skills add` под Node 20 падает (`fs/promises` без `glob`), поэтому CLI
запускают через `npx node@22`: так команда не зависит от того, каким `node` набран
PATH. В проекте разворачивать нечего.

Что это **не** значит: что вендорный код не читается. Мы не исполняем его и не
включаем в сборку, но тексты скилов — референс по процессу: систематическая
отладка, проверка перед объявлением готовности, дисциплина ревью.

## 5. Markdown

- 120 символов на строку; для таблиц ограничение отключено (`MD013.tables: false`), иначе матрицы
  из `docs/KIT.md` физически не собираются.
- Таблицы выровнены по `|` (`MD060: aligned`).
- У каждого блока кода указан язык: `bash`, `ts`, `tsx`, `css`, `json`, `text`.
- JSX размечается как `tsx`, не `typescript` — иначе WebStorm парсит `<Component />` как сравнение.
- Пути, которых ещё нет (план), помечаются в строке тегом `[plan]` — проверка `check:docs` их пропускает.

```bash
npm run lint:md
```

## 5a. Эталонные ширины

| Что                         | Значение                                             | Чем проверяется                 |
| --------------------------- | ---------------------------------------------------- | ------------------------------- |
| Эталон вёрстки и скриншотов | **1440 × 900**, DPR 1                                | `npm run shots`, кадр в README  |
| Контейнер страницы          | **1400 px**, отступ 24 px                            | `checkScale` в `verify:effects` |
| Сайдбар каталога            | 260 px от 1024, **300 px** от 1280                   | `checkScale`                    |
| Стена кита                  | 3 колонки от 1024, **4 колонки** от 1536             | `checkScale`                    |
| Переполнение                | нет на 390/768/1024/1280/1440/1680/1920              | `checkOverflow`                 |
| Узкий экран                 | 390 px — только проверка адаптива, не основа вёрстки | `shots` (`v20-m-*`)             |

Правило брейкпоинтов: писать `lg:` / `xl:` / `2xl:`, а не `min-[Npx]:`. Произвольный вариант
встаёт в CSS раньше именованных и молча проигрывает каскаду — так `min-[1440px]:grid-cols-4`
однажды не сработал вовсе.

`check:docs` — не формальность: он ловит ссылки на несуществующие скрипты и файлы, блоки кода без
языка и расхождение `.nvmrc` с `engines.node`. Именно он не даёт докам разойтись с кодом.

### 6a. Мутационный аудит

Зелёный гейт ничего не доказывает, пока ломающая мутация не покраснела. Два скрипта:

- `npm run mutate` — 15 статических мутаций, каждая в свежей копии репозитория;
- `npm run mutate:live` — мутации, которые видны только на отрисованной странице: сборка, сервер на
  3100, затем гейт; файл возвращается в исходное состояние всегда.

| Мутация               | Сломанное место                                       | Обязан покраснеть   |
| --------------------- | ----------------------------------------------------- | ------------------- |
| `props-drift`         | пропс в типе, но не в паспорте                        | `verify:props`      |
| `props-undocumented`  | пропс в паспорте, но не в типе                        | `verify:props`      |
| `cn-merge-broken`     | `cn` перестал различать оси утилит                    | `verify:merge`      |
| `readme-number-drift` | число компонентов в README                            | `verify:claims`     |
| `spelled-number`      | числительное словом вместо `kitStats()`               | `verify:claims`     |
| `composition-ghost`   | состав паттерна ссылается на несуществующий компонент | `verify:patterns`   |
| `demo-unregistered`   | демо выпало из реестра                                | `verify:kit`        |
| `surface-orphan`      | поверхность манифеста не попала в вид «по месту»      | `verify:kit`        |
| `claim-ghost-place`   | поверхность без подписи                               | `verify:kit`        |
| `source-missing`      | запись без ссылки на оригинал                         | `verify:kit`        |
| `source-404`          | ссылка «источник» ведёт на 404                        | `verify:links`      |
| `console-left`        | `console.log` в компоненте                            | `lint`              |
| `emoji-in-ui`         | эмодзи в интерфейсе                                   | `lint`              |
| `long-file`           | файл длиннее 250 строк                                | `check:file-length` |
| `doc-ghost-path`      | документ ссылается на несуществующий скрипт           | `check:docs`        |
| `aria-missing`        | у переключателя вида пропал `aria-pressed`            | `mutate:live`       |
| `wall-header-lost`    | со стены кита пропала общая шапка                     | `mutate:live`       |

Мутации не входят в `verify:all`: статический прогон — это 15 копий репозитория, живой — две сборки
и сервер. Запускаются вручную при правках гейтов.

## 7. Git и коммиты

- Conventional Commits: `type(scope): описание`, типы `feat`, `fix`, `docs`, `style`, `refactor`,
  `test`, `chore`, `perf`, `ci`, `build`.
- `.husky/pre-commit` → `lint-staged` (prettier + eslint + markdownlint) и `check:file-length`.
- `.husky/commit-msg` → `commitlint` (`@commitlint/config-conventional`).
- `.husky/pre-push` → `lint` + `typecheck` + `check:docs`.
- CHANGELOG генерируется из коммитов: `npm run changelog`.

Хуки лежат в репозитории, но не активированы: каталог не под git. Включить — `npm run setup:hooks`.

## 8. Отличия от шаблона (осознанные)

| Отличие                                     | Причина                                                                                                              |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Скрипты проверок — `.mjs`, не `.ts`         | Шаблон запускает `node script.ts` на Node 22+; здесь Node 20, type-stripping нет                                     |
| `engines.node: >=22.22.2`, `.nvmrc` 22.22.2 | Нижняя граница по самому требовательному инструменту: markdownlint-cli 0.50 и TypeScript 7 требуют >=22              |
| Stylelint не подключён                      | CSS один файл (`app/globals.css`), Tailwind v4 CSS-first; правило `at-rule-no-unknown` всё равно пришлось бы глушить |
| Тестов нет                                  | Роль регрессии выполняет `verify:effects` (Playwright): консоль, темы, адаптив, reduced-motion                       |
| `MD013.tables: false`                       | Матрицы `docs/KIT.md` — широкие таблицы, это их смысл                                                                |
| Тег `[plan]` в доках                        | Позволяет описывать ещё не созданные файлы, не отключая проверку целиком                                             |
| Husky не активирован                        | Нет `.git`; ставится одной командой                                                                                  |
| README без бейджа CI                        | Бейдж ведёт на `github.com/<owner>/<repo>/actions`; remote ещё не задан, а битая ссылка хуже отсутствующей           |
| README без бейджа Stylelint                 | Stylelint в проекте не подключён: бейдж обещал бы проверку, которой нет                                              |

## 9. Чеклист перед коммитом

1. `npm run verify:code` — зелёный.
2. `npm run check:docs && npm run lint:md && npm run format:check` — зелёные.
3. Изменения видны в живой странице: `npm run verify:effects` (при правках UI/VFX).
4. Нет эмодзи и псевдографики, в доках нет путей, которых не существует (или они помечены `[plan]`).
5. Коммит в формате Conventional Commits.
